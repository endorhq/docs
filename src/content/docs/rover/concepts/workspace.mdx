A workspace is the independent folders where coding agents will apply their changes. Rover creates a separate workspace for each [task](/rover/reference/cli-reference/#task), making it possible to run multiple tasks in parallel without interference.

To create it, Rover uses the [`git` worktree feature](https://git-scm.com/docs/git-worktree). A worktree is a separate checkout of your repository, sharing the same `.git` folder. Imagine it as having multiple copies of your local repository, each in its own folder and a different branch, but all connected to the same git history.

## Workspace structure

When you create a new task, Rover will create a new worktree in the `.rover/tasks/<task-id>/workspace/` folder. This workspace starts from the branch you specify when [creating the task](/rover/reference/cli-reference/#task) (defaulting to the current branch). The coding agent will then apply changes directly in this workspace.

<FileTree>
- .rover/
  - tasks/
    - 1/
    - 2/
      - description.json
      - ...
      - workspace/
        - YOUR_README.md
        - ...
    - 3/
    - ...
</FileTree>

## Deleting a workspace

When you delete a task using `rover delete <task-id>`, Rover will also remove the associated workspace, cleaning up the worktree and all its files. 

If you delete the `.rover/tasks/X/workspace/` folder manually, you will need to prune the git worktree references using:

```sh
git worktree prune
```
